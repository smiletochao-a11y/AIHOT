# 透物志 · 三平台选题台

为小红书、抖音、微信视频号维护观众需求与原理资料。入口：登录站点后台后打开 `/admin/topic-desk`，或点击“透物志 → 三平台选题台”。

## 第一周怎么用

1. 在三个平台分别搜索手机散热、降噪耳机、刹车、电机、洗衣机等与你内容方向相关的物品与问题。关键词只是观察起点，不代表已经热门。
2. 新建一个明确的“为什么”问题，选择目标发布平台。记录具体作品链接或账号、标题、截图文件名，填写北京时间观察日期和提问原意。没有可见播放量就不填，不能拿点赞数推算播放量。
3. 同一个问题的不同观察放进同一张卡。计数是记录条数，不是独立人数；同一作品多次观察不能当作多人重复提问。
4. 到技术文档、拆解或专业科普中核对原理，将可支持的结论、适用条件写在资料备注里，再人工勾选“已核对”。本站已有资讯也可通过链接关联。
5. 写原理因果链、动画思路、未解决的问题及三个平台各自的开头方向。界面提示缺少的资料项，不预测爆款，不替你判定科学结论。
6. 人工挑选候选并标记制作进度，点“导出文稿任务”得到 Markdown，可交给 Video-kazi/文稿工具。当前是文件交接，没有直接调用 Video-kazi 或生成视频。

## 导入与备份

“导入与备份”可下载示例 JSON、选择文件或粘贴文本，格式是：

```json
{"format":"touwuzhi-topics-v1","topics":[{"id":"UUID","topic":{"question":"…"}}]}
```

上面只示意外层；完整字段请用界面下载的模板。每批最多100条，导出按100条分文件。所有条目先校验再事务写入，一条有错整批不写。同ID再次导入会跳过，不覆盖现有修改；需要编辑请在界面打开选题。备份保留ID，所以可安全重复导入。不同ID的同义题不会自动合并，导入前请先查选题库。

证据字段：平台、类型、观察日期、定位信息、实际观察、可选指标、数值、口径。未记录指标时数值是 `null`，不是0；有指标必须说明统计周期或榜单名称。三个平台指标始终保留原值，不跨平台累加。目标平台与证据平台独立，计划发布到某个平台不代表在那里观察到了热度。

## 接入状态

- 三个平台均为人工记录/JSON导入；无自动抓取、无自动登录、无定时推送、无付费调用。
- 微信视频号无公开链接时，可用账号、作品标题、截图文件名定位；不要导入个人身份信息或整段评论区。
- 信源清单是人工查阅入口，不是已试抓成功的爬虫配置；不会新增收费公众号采集服务。
- 百度指数仅用作外部参考，不冒充三个平台的需求指标。
- 原项目公共资讯引擎、分类、默认AI示范信源和评分阈值未替换。已有站点如要停用示范源，在后台暂停；仅替换种子文件不会删除既有信源。
- 自动筛选、跨来源语义归并和自动生成平台脚本尚未实现。先用真实记录校准，再决定模型评分；未经标注不更改原精选阈值。

## 部署与验证

遵循 `docs/deploy.md` 的备份、构建、停止服务、迁移、启动顺序。新增迁移 `0090_topic_desk.sql` 只创建模块自己的表，不删除旧数据。模块已注册到 `site/modules/`；Docker构建已包含包清单。无需新增密钥。

开发保持采集、模型和推送开关关闭。选题数据只经管理员接口读取，复用登录、CSRF保护和审计。写入使用版本号拒绝覆盖其他窗口的新编辑；遇到409请刷新后重新编辑。

```bash
npm ci --no-audit --no-fund
npm run typecheck
npm run test:standalone
DATABASE_URL=postgres://127.0.0.1:5432/touwuzhi_test npm test
npm run build -w @aihot/web
node --test apps/web/tests/*.test.ts
node scripts/smoke.ts --base http://localhost:3000
```

这是已有项目内的管理员模块，并未发布一个新公共站点；外部上线前仍须确认站名、品牌及使用/隐私说明。
